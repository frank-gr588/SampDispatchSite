# Оптимизация производительности фронтенда

## Проблема
Обновление информации, удаление и редактирование данных происходили медленно, особенно при работе с несколькими юнитами. Каждая операция вызывала множественные запросы к серверу.

## Решение

### 1. **Дебаунс запросов (300ms)**
Добавлен механизм дебаунса для всех refresh методов в `DataContext.tsx`:
- `refreshUnits()`
- `refreshSituations()`
- `refreshPlayers()`
- `refreshTacticalChannels()`

**Как работает:**
- При вызове `refresh()` без параметра `immediate` запрос откладывается на 300ms
- Если за это время поступит новый запрос, старый отменяется
- Только последний запрос выполняется фактически

**Результат:** Множественные вызовы refresh объединяются в один запрос.

### 2. **Защита от одновременных запросов**
Добавлены флаги `fetchingFlags` для предотвращения параллельных запросов к одному эндпоинту.

**Результат:** Предотвращены race conditions и дублирование запросов.

### 3. **Оптимизация интервалов обновления**
До:
- Игроки: каждые 5 секунд
- Ситуации: каждые 5 секунд  
- Каналы: каждые 10 секунд

После:
- Игроки: **каждую 1 секунду** (координаты в реальном времени)
- Ситуации: **каждую 1 секунду** (статусы обновляются быстро)
- Каналы: **каждые 2 секунды**

Благодаря дебаунсу частые обновления не создают лишней нагрузки.

### 4. **Батчинг обновлений после операций**
В `Index.tsx` убраны множественные вызовы `refresh()` после каждой операции:

**До:**
```typescript
await apiPost(...);
await refreshUnits();
await apiPut(...);
await refreshUnits();
await apiPost(...);
await refreshUnits();
await refreshSituations();
```

**После:**
```typescript
await apiPost(...);
await apiPut(...);
await apiPost(...);
// Один batch refresh
await Promise.all([refreshUnits(), refreshSituations()]);
```

### 5. **Удалены избыточные логи**
Убраны console.log из критических путей для уменьшения overhead.

## Итоговый результат

✅ **Обновления происходят ~в секунду** (вместо 5-10 секунд)
✅ **Нет дублирования запросов** (благодаря дебаунсу и флагам)
✅ **Плавный UI** (батчинг и оптимизация)
✅ **Меньше нагрузки на сервер** (объединение запросов)

## Технические детали

### DataContext.tsx
- Добавлен `useRef` для таймеров дебаунса
- Добавлен `useRef` для флагов fetching
- Все refresh методы поддерживают параметр `immediate`
- Cleanup таймеров при размонтировании

### Index.tsx
- Интервалы обновления: 1s (players/situations), 2s (channels)
- Убраны избыточные refresh после каждой операции
- Объединенные batch refresh через `Promise.all()`

## Миграция

Все изменения обратно совместимы. Вызовы без параметров работают как раньше, но с дебаунсом:

```typescript
// Старый код продолжает работать
await refreshUnits();

// Новая возможность: immediate запрос без дебаунса
await refreshUnits(true);
```
